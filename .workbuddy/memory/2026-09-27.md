## 摸清发布链路的实证（供以后排查用）
日志正本：`~/.workbuddy/logs/sites/sites-deploy-YYYYMMDD.log`（DEBUG 级，含全部请求体/响应体）
+ `~/.workbuddy/cloudstudio-deploy-history/<workspaceKey>_<ts>.json`（每次部署一条：sandboxId / conversationId / appId / shareLink / language / contentHash）

三步（本次全程 19.4s）：
1. **认应用**：`GET https://www.workbuddy.cn/console/as/genie-baas/control/applications?sort=updatedAt&pageSize=200`
   （按目录匹配）→ `GET .../applications/detail?applicationId=`
2. **进沙箱**：复用旧 `sandboxId`（不新建）；探测 `language=node port=3000 install="npm install" start="npm run start"`；
   打包 tar.gz 上传沙箱 `/filesystem/workspace/site-bundle.tar.gz`（本次 8.84MB，已排除 node_modules/.git）
   → 解包 → `npm install` → `POST /replaceCloudStudioConfig`（注册自启）→ 起 `PORT=3000 npm run start`
   → 轮询验 HTTP 200（本次第 2 次尝试通过）
3. **挂域名+登记**：`POST /console/as/artifact-releases`
   （body: artifactType=web / persistent=true / expire=157680000≈5年 / useAppNameAsDomain=true / skipFork=true）
   → 得 `releaseUrl` → 回访验证 200 → `POST .../applications/publish`（appId+sandboxId+shareLink）→ 状态 published
   → 最后抓封面 `POST /genie/api/project/<conv>/cover-from-sandbox`（本次 404，**失败被忽略，不影响发布**）

- 沙箱是 e2b（`<port>-<sandboxId>.e2b.sh4.sandbox.cloudstudio.club`）：执行命令 `POST /console`、传文件 `POST /filesystem/<path>`，带一次性 token。
- ⚠️ **这些控制面 HTTP 接口没有开放 API key / 公开文档**，走 WorkBuddy 登录态（控制台 session + Origin 校验）；
  🚫 不要把「抓 cookie 直连内部接口」当自动化方案推荐给用户 —— 会随版本变、无支持、且属绕过产品入口。
  要自动化就走「对话 / 定时任务触发 `workbuddy_sites_deploy`」这条路。
- 本机**没有** codebuddy / workbuddy CLI（`/c/nvm4w/nodejs/` 下只有 agently-cli、clawdhub、codex）。
