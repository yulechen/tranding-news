## 云端信息库（新建并上线）

**目标**：用户在微信里让 WorkBuddy 生成 HTML，统一归档到一个云端页面查看。

**交付**
- 云应用「云端信息库」，appId `wbapp_nYUBg7YCbzNbEX9V2pDJ4d`
- 线上地址：https://info-vault.app.workbuddy.host/
- 数据表 `documents`，正文存在 `content` 字段
- 前端 `public/`（index.html / styles.css / app.js / config.js / vendor 自托管 SDK）
- 后端 `server.js` 零依赖 Node：静态托管 + `/api/inbox` 收件箱
- 工具 `tools/push.mjs`（Agent 推送）、`tools/selfcheck.mjs`（18 项自检）

**需求变更（同日）**
最初做成「邮箱登录 + owner 隔离 + 云对象存储」，用户随后明确要求
「不需要注册验证，全部都可以看」。于是整体改为公开：
RLS 四条策略全部放开为 `true`、`owner_id` 允许为空、
正文从对象存储改存数据库 TEXT 字段（Storage 必须登录才能读，与公开诉求直接冲突）。

**踩坑记录**
- Auth 只在正式发布域名生效，localhost 与内置预览都用不了
- 云存储只支持 `users/<uid>/...` 与 `shared/<ownerUid>/...`，且必须登录
- 云数据库是 PostgREST + RLS，客户端不得传 `owner_id`（由 `DEFAULT auth.uid()` 填）；
  公开表要同时做 GRANT 和策略两道门
- 平台网关占用 `/healthz`，会返回平台自己的探针响应 → 应用改用 `/api/health`
- 本机 bash 缺 coreutils（`dirname` / `ls` 不可用），文件操作一律用 node
- selfcheck 里 `waitForServer` 的 health 路径改过一次没落盘，误报「服务未响应」，重新改后正常

## 网站图标设计（同日）

原图标是靛蓝方块 + 一个「W」形折线，读不出「库」的含义。重做为「云 + 收纳盒」：
云朵压在开口托盘上方，配站点既有的靛蓝→青渐变。

**形状构造要点（易踩坑）**
- 云朵一开始用「3 个圆 + 圆角矩形」拼接，圆形与矩形圆角处会出现肉眼可见的凹口。
  原因是矩形的圆角圆心到圆的距离 + 圆角半径 > 圆的半径，圆角露在了圆外。
- 正确做法：让矩形的左右边缘**正好落在左右两个圆的圆心 x 上**（矩形 rx 设 0），
  这样矩形角点就在圆心上，一定被圆包住；且圆与底边相切，底边自然过渡，无接缝。
  最终云形 = 4 个图元（3 圆 + 1 直角矩形），底边 x∈[11.7, 20.7] 平直。

**方案对比**（三版都渲染成 PNG 实际看过）
- A 云台：云 + 一条横杠 → 干净，但横杠像游离的短横，语义弱
- B 云归档：云 + 下箭头 → 动作感强，但箭头偏细、易读成字母 V
- C 收录盒：云 + 开口托盘 → **选定**，语义最足且小尺寸仍可辨

**产出文件**
- `public/favicon.svg` —— 主图标（矢量，浏览器首选）
- `public/apple-touch-icon.png` / `favicon-32.png` / `favicon.ico` —— 位图兜底
- `design/favicon-a|b|c.svg` + `design/preview/*.png` —— 备选方案与对比图
- `tools/make-icons.mjs` —— SVG → PNG/ICO 光栅化（含手写 ICO 封装）
- index.html 的顶栏 brand-mark 与启动页 boot-mark 换成同一 glyph（fill/stroke 用 currentColor）

**新增工具链**
`@resvg/resvg-js` 装在托管 Node 工作区（`C:/Users/chenq/.workbuddy/binaries/node/workspace`），
项目里用 `createRequire('<workspace>/noop.js')` 解析，**不往项目 node_modules 里装**（否则会被一起部署）。

**自检**：从 18 项扩到 20 项，新增 `GET /favicon.svg` 与「图标引用正确」，全绿。

## 收藏夹入口（同日）

**用户痛点**：星标只是卡片角落的一个小图标，收藏完还是得在列表里翻 —— 没法快速找到。

**改动**
- 工具条第一个位置加「收藏」筛选 chip（琥珀色，独立于内容类型，用竖线分隔）；
  点击在「全部」和「只看收藏」之间切换。收藏视角下**类型计数与标签行都按收藏子集重算**，
  避免出现「报告 3」但收藏里只有 1 个报告这种对不上的情况。
- 已收藏的卡片加 `is-starred`：暖色描边 + 常驻琥珀色顶条（普通卡片顶条只在 hover 时出现）。
- 预览页顶栏新增收藏按钮（读完想收藏不用退出去），状态与卡片实时同步。
- **深链**：收藏视角写进地址栏 `#fav`，可直接存成书签一步到位；`hashchange` 也监听，
  浏览器前进后退可用。切换收藏视角时会清掉已选标签，否则标签可能被筛掉后从行里消失、看不出还选着。

**顺带解决的一个旧问题**：本机其实不用装 playwright 也能做截图级验证 ——
本机已装 Chrome / Edge，用 `--headless=new --remote-debugging-port` 起无头实例，
再用 Node 内置 `WebSocket` 走 CDP（`Runtime.evaluate` 执行一段 JS 后可 `Page.captureScreenshot`），
就能拍「点开卡片之后」「切到收藏视角之后」这类交互后的状态，而不是只能拍首屏。
封装成了 `tools/shot.mjs`（零依赖，自动找浏览器、自动清理 profile）。

**验证**
- 本地自检 21/21（新增「收藏入口已就位」）
- 匿名身份跑收藏数据链路 6/6：列表带 starred 字段、收藏写入生效、收藏数 +1、取消收藏、恢复原状
- CDP 实测交互：点开卡片 → 预览页显示「已收藏」→ 点一下变「收藏」，
  同时芯片计数归零、卡片星标样式消失 —— 整条回路真实跑通（截图见 `design/preview/ui-*.png`）

## 标签改由用户自己维护（同日）

**用户反馈**：「标签太凌乱了，推送数据不能设置标签，标签我自己维护。」

**诊断**：查库发现 4 条内容上共 21 个标签，**全部**来自推送时的 `--tags`，
其中 19 个只出现过一次。也就是说这些标签是机器按标题临时拆的词，没有任何一个是人工维护的 ——
典型的"推一条内容就多 5 个标签"，很快把标签区撑成 4 行碎片，筛选反而更难用。

**改动**
- `tools/push.mjs`：`tags` 强制写 `[]`（`publishDirect` 与 payload 两处）；
  `--tags` 参数保留但**忽略**并打印提示 —— 这样旧的定时任务/脚本不会因为未知参数报错。
  帮助文本与文件头都写明了「推送不设置标签」及其原因。
- 前端加「已有标签」快捷追加：编辑弹窗和添加弹窗的标签输入框下方，
  列出库里已有标签（排除已填的、按使用次数降序、最多 12 个），点一下追加进输入框。
  目的是**引导复用同一个词**，从源头防止再堆出近义词。
- 抽了公共函数 `tagCounts(list)`（工具栏标签行和快捷追加共用）、`splitTags(v)`，顺手替换掉两处重复的 split 逻辑。
- 清理存量：4 条内容的标签全部置空（备份在 `.workbuddy/memory/tags-backup-2026-09-19.json`，含原标签）。

**验证**
- 真实推送测试：故意传 `--tags "美股,盘前,AI算力"`，入库记录 `tags` 确认为 `[]`，测试记录已删
- CDP 实测：标签行从 4 行 21 个收敛成一行；编辑弹窗「已有标签」只显示未使用的；
  点一下输入框从 `比特币, 资金面` 变成 `比特币, 资金面, 全球市场`，候选里 `全球市场` 随即消失
- 自检扩到 22 项，新增「标签由人工维护」（校验页面有快捷追加区 + 读本地 push.mjs 断言它不再透传标签）
- 本地 22/22、线上 22/22 全绿；线上实测 `tag-row` 已隐藏、卡片无标签

**注意**：验证用的临时标签（#7 比特币/资金面、#5 全球市场/早报）已清空，库里标签数为 0，
留给用户从零开始维护。#7「BTC 市场监控」被用户自己标了收藏（非我操作）。

## 去掉搜索与上传入口，标签成为主要组织方式（同日）

**用户要求**：「取消添加数据按钮和搜索，我可以手动给每个页面添加标签，按照顶部我自己打的标签进行过滤。」

**解读**：内容只从 WorkBuddy 推过来，用户不再手动传；查找完全靠标签。
所以标签必须从「藏在编辑弹窗里的一个字段」升级成**一等操作**。

**改动**
- 删掉顶栏搜索框、删掉「添加内容」按钮、删掉整个上传弹窗（含拖拽区/文件选择/粘贴 HTML）及对应的
  `openUpload` / `closeUpload` / `renderPicked` / `addFiles` / `confirmUpload` 与 `view.q` 过滤逻辑。
  顶栏现在只剩品牌 + 刷新。**收件箱链路保留**（`archiveOne` 仍被「全部入库」使用，且归档时 tags 强制 `[]`）。
- **每张卡片右上角新增标签按钮**（在星标左侧）：点一下直接开标签弹窗，不用先进预览页。
  打过标签的常亮靛蓝，没打的是灰的 —— 扫一眼就知道哪几条还没归类。
- **新增「编辑标签」弹窗**（`#tag-modal`），交互按「最快打完」设计：
  - 输入框：回车 / 中英文逗号即时确认，一次输入多个词会一起进（复用 `splitTags`）；
  - 当前标签：chip 形式，✕ 直接移除，输入框空着时按退格删最后一个；
  - 已有标签池：点一下加入、再点移除（已选的实心高亮）—— 引导复用同一个词；
  - 上限 12 个（`MAX_TAGS`），超出会在弹窗里提示。
  - 底部「取消 / 保存」，保存才落库（草稿放在 `tagDraft`，不污染 `docs`）。
- 预览页顶栏也加了「标签」按钮（`data-act="tag"`），看内容时想归类不用退回列表。
- 标签为空时**不再整行隐藏**，改成显示引导语「点卡片右上角的标签按钮，给内容归个类」——
  否则新用户根本发现不了这个功能。

**顺手修掉的分面计数 bug**
原来类型 chip 的计数只按「收藏」算，标签过滤不参与，于是筛出 1 条时 chip 还写着「报告 3 页面 1」，
点「页面」直接是空列表。改成：
- 类型计数看「收藏 + 标签」之后的结果（`afterTag`）
- 标签 pill 计数看「收藏 + 类型」之后的结果（`afterType`）
- 另外若选中的标签被类型筛成 0 条，仍把它保留在标签行里（`unshift([view.tag, 0])`），
  否则用户看不到自己卡在哪个筛选上、也退不出来。

**验证**

- CDP 实测：顶栏只剩「刷新」；标签行 8 个 pill；卡片 4 个标签按钮
- 标签弹窗：当前标签 `加密✕ 资金面✕`、候选池正确高亮已选；输入「行情, 测试」回车 → 两个词都进去且输入框清空；
  点候选「A股」→ 加入，`tag-current` 变 5 个
- 标签过滤：点「全球市场」→ 4 条变 1 条，类型 chip 同步收成「全部 1 / 报告 1」
- 完整落库链路：卡片 → 标签按钮 → 输入 → 保存 → toast「标签已更新（2 个）」→ 标签行立刻多出该标签
- 验证用的标签已全部清空（库回到 0 标签），截图见 `design/preview/ui-v2-*.png`
